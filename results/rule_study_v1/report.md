# 规则发现实验：联合统计有效，但仍需理解访问顺序

日期：2026-10-08。Python 3.10.11，后端仍为 `toy-fcfs-v1`。本轮由当前对话提出假设、实现规则、调用工具并分析反例；没有新增自主 Agent 服务，也没有接入 Ramulator 或真实 KV 请求。

**结论：旧启发式确有可解释的缺口。新规则在两个发现样例上达到位排列空间的最优值，但在验证中存在退化。此次产物是一个可复用的规则假设及其失效证据，不是 Agent 优于传统搜索的证明。**

定位说明：本轮属于规则发现的支线诊断，为后续 Agent 探索提供开发案例、强基线与可选分析工具。项目主线是 [Agent 持续主导策略探索](../../docs/RESEARCH_POSITIONING.md#agent-mainline)，需要直接比较其多轮决策的效果和成本；本报告中的确定性规则结果不能代替这一证据。

## 实验边界与复现

原有 `activity_policy(pack_columns=True)` 与模拟器保持不变。实验代码见 [rule_study.py](../../hbm_toy/rule_study.py)，测试见 [test_rule_study.py](../../tests/test_rule_study.py)。

- 缩小配置：6 位块地址，4 个 channel × 每 channel 2 个 bank，2 个 column × 4 个 row，64 字节粒度；每条轨迹 256 次请求，每周期到达 8 次。
- 完整枚举 6! = **720 种位排列**，所有排列均可在原 DSL 操作数限制内表达。这里的“最优”只覆盖位排列，不包含 XOR，也不覆盖原来的 16 位空间。
- 2 个发现样例；规则与代码固定后，再运行预先列出的 12 个验证变体。另在原有 16 位配置的 8 条轨迹上检查规则适用性，不做大空间穷举。
- 每个小空间样例均有随机排列搜索、局部排列搜索对照，各 3 个种子、每次 20 个不同映射的实际评价。两者都以 identity 和旧启发式为起点；若两者相同，只评价一次。局部搜索包含周期性随机重启。
- 规则生成不调用性能后端；生成后各测量一次。精确枚举和搜索对照的结果不参与规则生成。新规则读取与旧规则相同的完整请求轨迹，但使用不同统计。

预先声明的假设、验证集合与源码 SHA-256 在 [protocol.json](protocol.json)。[discovery.json](discovery.json) 与 [validation.json](validation.json) 保存规则 DSL、指标、搜索历史、全部排列的完成时间和耗时。验证前及整理结果时均核对源码哈希一致。

两轮共记录 **11,848 次后端执行**：14 个小空间样例各执行 4 次规则测量、120 次搜索评价和 720 次枚举，再加原有轨迹的 32 次规则测量。不包含单元测试；模型思考时间、token 和人工设计成本未测量，不能据此声称总研究成本更低。

在项目根目录运行，使用新的输出目录，不覆盖归档：

```powershell
python -m unittest discover -s tests -v
python -m hbm_toy.rule_study discovery --output results/my_rule_study
python -m hbm_toy.rule_study validation --output results/my_rule_study
```

发现阶段创建目录；验证阶段拒绝源码变化或覆盖已有验证结果。命令生成三个 JSON 文件，本报告是根据归档结果撰写的分析，不由命令自动生成。

## 假设与可固化规则

旧规则按单个位的翻转率安排 channel、bank、column。它可能将高度相关的位误认为独立的并行资源选择信号。

发现样例将一个五位计数器 `x` 编码到六位地址，位号从低到高：

- `duplicate`：`[x0, x0, x1, x2, x3, x4]`。前两个位同时翻转，用它们选 channel 只能访问两个 channel。
- `parity`：`[x0, x0 XOR x1, x1, x2, x3, x4]`。前三个位各自活跃，但只有两个独立维度；用它们选择 channel/bank 时，每个 channel 只使用一个 bank。

这些负载是针对已知缺口构造的诊断样例。它们不能证明此种相关性在真实 KV 请求中的出现频率。

实验实现两个普通确定性算法：

| 规则 | channel/bank 位选择 | column 位选择 |
| --- | --- | --- |
| `activity_packed`，冻结的旧规则 | 全局位翻转率 | 全局位翻转率 |
| `joint_only`，消融对照 | 逐位最小化组合桶请求数平方和，倾向均衡联合分布 | 全局位翻转率 |
| `joint_conditional`，新规则 | 同上；平局时比较全局翻转次数，再比较位号 | 按同一 channel/bank 内相邻请求的位翻转次数排序 |

新规则的解释是：**先避免相关位浪费并行资源，再让 column 吸收同一 bank 内频繁变化的位。** 其产物是根据轨迹特征生成映射的程序，不是一个只能用于单条轨迹的固定 DSL。

## 发现样例：从缺口到规则

完成周期越小越好：

| 样例 | 旧规则 | 仅联合选择 | 联合选择＋条件 column | 720 种排列最优 |
| --- | ---: | ---: | ---: | ---: |
| duplicate_ordered | 1020 | 764 | **508** | 508 |
| parity_ordered | 1016 | 764 | **508** | 508 |

在 duplicate 样例上，新规则把请求从两个 channel 分散到四个，并让八个 channel/bank 组合各承担 32 次请求。仅修复联合分布时，column 仍被条件下不变化的冗余位占据，行命中率为 0%；进一步改变 column 选择后，行命中率恢复到 50%，完成时间下降到 508。

两类样例分别有 24、36 个排列达到最优，最优映射并不唯一。传统局部搜索的 6 次运行中，5 次也达到精确最优；随机搜索为 2/6。新规则的优势是无需后端搜索即可在这两个样例上生成好策略，但发现规则的成本尚未与其他方法公平比较。

## 冻结后的验证：收益与反例一起保留

数字种子改变地址位布局；`shuffled` 还打乱访问顺序。同一 family、同一种子的 ordered/shuffled 对包含完全相同的地址及访问次数，区别在于顺序。`phase_mix` 在前后两个阶段使用不同位布局，`repeated_bursts` 对地址进行连续重复访问。

| 验证样例 | 旧规则 | 新规则 | 排列空间最优 |
| --- | ---: | ---: | ---: |
| duplicate_ordered_101 | 1020 | **508** | 508 |
| duplicate_ordered_303 | 1020 | **508** | 508 |
| duplicate_shuffled_101 | **827** | 959 | 796 |
| duplicate_shuffled_303 | 1876 | **825** | 731 |
| parity_ordered_101 | 1016 | **508** | 508 |
| parity_ordered_303 | 1016 | **508** | 508 |
| parity_shuffled_101 | 970 | 970 | 788 |
| parity_shuffled_303 | 1401 | **825** | 769 |
| full_ordered | 508 | 508 | 508 |
| full_shuffled | 1036 | **976** | 910 |
| phase_mix | 1740 | **839** | 510 |
| repeated_bursts | 544 | 544 | 544 |

新规则相对旧规则 **8 胜、3 平、1 负**，6/12 达到排列空间最优。这些变体属于已知生成器家族，不是 12 个独立真实应用，不能把胜率外推为普遍收益。验证输出在规则冻结后才运行，但生成器对设计者可见，因此不是严格盲测。

局部搜索的 36 次验证运行中有 17 次达到最优，随机搜索为 13/36。尤其在 `phase_mix` 上，局部搜索三个种子得到 636、637、510，新规则为 839。这是简单贪心规则尚未解决的权衡，也说明传统搜索对照不能省略。两种方法的后端评价次数不同，不应只比较最终分数就判断效率优劣。

### 反例揭示了什么

在 `duplicate_shuffled_101` 上，旧规则与新规则的 channel/bank 请求量都完全均衡，但完成时间从 827 退化到 959，约慢 **16.0%**。新规则的行命中率从旧规则的 46.09% 降到 19.92%。

检查同一 bank 内的 248 对相邻请求，得到：

| 候选 column 位 | 该位翻转次数 | 只有该位变化的次数 |
| --- | ---: | ---: |
| bit 0 | 128 | 67 |
| bit 1 | 130 | 0 |
| bit 4 | 130 | 0 |

新规则选择 bit 1，但它与 bit 4 总是同时变化。把 bit 1 移入 column 后，bit 4 仍在 row，因而无法避免换行。旧规则选择 bit 0，恰好保留了另外 67 次行命中。

**可固化规则需要理解联合变化，不能只把“全局单个位统计”换成“bank 内单个位统计”。** 给定 channel/bank 映射后，令相邻请求块地址的 XOR 为 `delta`、row 位集合为 `row_mask`，当前模型中的行命中要求 `delta & row_mask == 0`。下一版可以直接统计这个条件，比较 column 组合，而非仅排序各位翻转次数。这里记录的是反例导出的后续假设，本轮没有据此修改规则并重新使用同一验证集报告改进。

即使更准确地预测行命中，仍需评价最终完成时间；row 局部性、bank 访问顺序与并行性之间仍可能存在权衡。

## 回到原有 16 位负载

这里检验的是**规则迁移**：每种规则可以读取目标轨迹的地址特征并重新生成映射，但不读取其性能反馈来选择候选。这与首轮“把训练选出的固定映射直接放到变体上运行”不同，下面的数字不能与首轮固定映射的变体分数直接混用。

| 原有轨迹 | 旧规则 | 新规则 |
| --- | ---: | ---: |
| sequential 原始 / 变体 | 796 / 804 | 796 / 804 |
| stride 原始 / 变体 | 796 / 844 | 796 / 844 |
| kv_interleaved 原始 | 796 | 796 |
| kv_interleaved 变体 | **1773** | 2163 |
| random 原始 | 2516 | **2361** |
| random 变体 | **2392** | 2428 |

新规则在原有 KV 变体上退化约 **22.0%**，进一步说明它还不能替换旧规则成为通用方案。原有轨迹已在前轮研究中使用，这部分是兼容性与适用性检查，不是新的独立测试集。

## 对研究定位的影响

1. **无需先增加 HBM 复杂度，就能让现有启发式暴露缺口。** 地址位相关性、访问顺序和阶段变化已经带来差异；名义搜索空间大小不是唯一因素。
2. **Agent 可以帮助提出并固化规则，同时需要主动寻找反例。** 本轮留下了新规则、消融对照、适用样例和失效机制；简单程序负责重复生成策略。
3. **尚未建立 Agent 的比较优势或规则的新颖性。** 联合统计是常规数学工具，局部搜索也能找到好解；本轮没有人工设计成本对照，也没有多个独立 Agent 运行。
4. **后续主线转向 Agent 主导的受控探索。** 用本轮反例作为开发数据，在新的评价任务中检验 Agent 能否诊断失败、修正假设并自主选择下一步实验。联合变化统计可继续作为支线或可调用工具研究；工具是否使用及预算如何分配，应纳入 Agent 决策的对照。真实请求验证与更真实后端复核仍需补齐，具体计划见 [下一轮实验](../../docs/RESEARCH_POSITIONING.md#next-agent-study)。

本轮新增与原有测试共 15 项通过。覆盖全部 720 种排列的编译和逆映射、相关位造成的资源闲置、默认配置的 DSL 操作预算，以及搜索实际评价计数和重放。没有 RTL 仿真或真实 HBM 性能结论。
