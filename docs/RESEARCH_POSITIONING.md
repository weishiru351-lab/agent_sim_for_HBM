# 研究定位：Agent 主导探索，以公平实验检验能力

更新日期：2026-10-08。本文维护当前研究判断、开发原则与推进条件。依据是 20 篇文献的有范围精读和已有玩具实验，**不是对论文的独立复现，也不是已经成立的 Agent 优势**。论文入口见[文献阅读指南](LITERATURE_GUIDE.md)，章节证据、数字口径及认识修订见[研究笔记](RESEARCH_NOTES.md)；本文将这些认识转成后续工作的决策依据。

## 当前研究判断

**主攻方向调整为：面向负载特征与数据生命周期，由 Agent 在有限评价预算下主导内存数据组织策略的受约束探索。** HBM/KV 是切入场景；先选择一个有明确取舍的子问题，再确定需要开放哪些布局、分配、映射或转换原语。纯地址位搜索保留为基础对照、诊断工具和可能的内层子问题，不再作为长期主线。

研究价值分成两个尚需分别验证的问题：目标平台上是否存在强方案尚未充分解决的优化余量；Agent 是否比共享同样信息与工具的搜索方法更有效地利用这份余量。已有文献支持继续寻找这样的任务，尚不支持“HBM 更复杂，Agent 自然会赢”。

## 两条平台路线

平台暂不限定，先比较实际自由度。下表是基于文献与当前项目状态的研究建议。

| 维度 | 路线 A：可修改控制器/定制硬件 | 路线 B：现有 GPU 推理软件 |
| --- | --- | --- |
| 优化对象 | 布局、分配与可实现的控制器映射协同；选 NPU/PIM 子路线时还需考虑计算访问组织 | KV 布局、分块、分配、页管理及访问组织 |
| 可控制范围 | 以架构/IP 为边界，确认地址转换、区域粒度、命令和必要硬件改动；位选择/XOR 只是其中一层 | 以设备、驱动和框架已开放接口为边界 |
| 关键相关工作 | [SDAM](LITERATURE_GUIDE.md#r02)、[Flatfish](LITERATURE_GUIDE.md#r03)、[XOR 数学模型](LITERATURE_GUIDE.md#r04)；NPU/PIM 子路线重点对照已读的 [PFM](LITERATURE_GUIDE.md#r14)、[PATTON](LITERATURE_GUIDE.md#r15)、[UMDAM](LITERATURE_GUIDE.md#r20) | [PagedAttention](LITERATURE_GUIDE.md#r12) 与 [vAttention](LITERATURE_GUIDE.md#r13) |
| 评价方式 | DRAM 时序仿真及可信请求模型；必要时加入系统仿真、RTL 综合/验证或原型 | GPU 实测、系统剖析与端到端推理评价 |
| 主要难点 | 请求流真实性、映射与调度耦合、实现成本、切换时的数据一致性 | 区分缓存、合并访问、kernel 与分配收益；既有系统基线很强 |
| 有价值的产物 | Agent 探索证据，以及可实现的联合策略、适用条件与完整成本 | Agent 探索证据，以及可部署的数据组织与分配方法和完整开销下的收益 |
| 与当前玩具的距离 | 映射子层可复用；系统任务仍需对象/依赖前端、成本与实现约束，不能只换后端 | 需要调整 DSL 层级及评价边界，当前位映射 DSL 不能直接部署 |
| 适合的团队资源 | 控制器、RTL、体系结构或仿真经验 | GPU、推理框架与 kernel 开发经验 |

现有 GPU 的虚拟内存/分配控制能力不能直接视为可重编程的 HBM bank 映射。定制 NPU/PIM 的设计也不能直接作为普通 GPU 的能力证明。具体 IP 的限制见 [厂商资料](LITERATURE_GUIDE.md#vendor-docs)。

分析 KV 问题时，沿着下面的因果链检查，而不是从张量形式不同直接跳到映射需求不同：

```text
KV 结构与数据布局
    → kernel 访问顺序与分配
    → 缓存、请求合并、地址转换
    → 到达控制器的请求流
    → 地址映射与调度
    → 介质执行和最终性能
```

这条链还包含反馈：容量不足可能触发 eviction/recompute，完成事件可能推迟后续计算与请求生成。布局或分配改变这些事件时，应固定上层逻辑工作负载，允许下层请求随策略变化；固定物理请求轨迹只适用于明确保持流量不变的子问题。

<a id="minimal-system-task"></a>
## 优先收敛的系统问题

**优先候选是 KV 块生命周期中的“追加写入—后续读取/归约—容量占用”取舍。** 这是从 PFM/PATTON 等工作提炼的问题方向，不是已经选定的平台或新机制。现有专门方案已解决部分问题，下一步必须说明剩余问题在哪里，不能把重现其策略当作创新。

先在两条平台路线下各列一份可控操作清单，再选其中一条进入最小任务。NPU/PIM 具有较直接的读写冲突证据，但需要明确命令与架构支持；普通 GPU 路线需要重新确认 kernel、分配和容量上的真实冲突，不能直接采用 PIM 的代价模型。HBM 仍是主要背景，引用 AiM/GDDR6 证据时保留介质与计算架构边界。

| 逐步考虑的子问题 | 必须同时计入的取舍 | 应先比较的机制基线 |
| --- | --- | --- |
| 固定容量下的一种 KV 块：写入友好布局与读取/归约友好布局 | 完整读写路径、操作次数、有效传输及结果回收 | 静态布局、解析代价选择、结构化搜索 |
| 若生命周期确有额外影响，再加入 partial/full、填满提交与早停 | 未满块读取、搬移、暂存和目标预留、发布/回收顺序 | 固定提交策略、阈值策略、适用平台的已有专门机制 |
| 若容量压力是主要矛盾，再加入共享、淘汰与重计算 | 有效容量、共享命中、额外计算及服务完成时间 | 容量感知分配与缓存策略，并做机制消融 |

这不是三个必须依次开发的版本。若第一项已被简单规则充分解决，应明确这一结论；只有下一项对应真实使用情形，才有理由扩展。暂不同时引入多介质迁移、任意命令调度、任意 RTL 合成或完整推理服务。

最小任务规格应先写清：平台及控制权限；逻辑对象和操作；必要生命周期状态；合法策略与禁止操作；请求生成及依赖；容量和转换成本；数据正确性不变量；主要目标及约束；强基线；开发/未见任务划分。例子和代价关系应能手算核验，再决定新增代码。

<a id="dsl-design-principles"></a>
## DSL 与模型的设计原则

DSL 是可执行策略的语义契约，不只是 JSON 语法或几种完整方案的名字。以下是未来设计约束，不代表现有 `swap_bits` / `xor_bit` 已具备这些能力。

- **分开描述固定任务与候选策略。** shape、dtype、逻辑操作、硬件容量、允许控制范围及目标由任务定义；候选只能改变允许的布局、分配或转换。不能通过少读数据、取消写入或扩大容量获得假收益。
- **原语来自机制并允许组合。** 可按所选子问题引入分块、维度排列、对象分区、受限分配和状态转换。保留静态布局与运行时状态两层语义，不用单一 `use_PATTON` 代替设计空间，也不一次放开所有层。
- **正确性覆盖全局和时间。** 各局部映射可逆，不保证对象互不重叠或转换前后读到同一数据。需验证跨对象范围、共享/引用、写后读、搬移完成后发布位置、回收，以及操作所需数值语义。
- **表达能力和搜索能力分开评价。** 表达式相同、映射函数相同、模型中的性能等价、一次实验同分是四件事。增加 XOR 或状态原语后，共同更新基线空间及合法性检查；旧排列 oracle 不能继续证明新空间最优。
- **不要靠增加语法制造困难。** 当前 720 排列在模型字段重编号下有 180 组已审计的等价分组，仍可能有局部障碍；名义数量不代表有效难度。这是有限离散问题，不是普通凸优化；结构化求解有效也不等于凸性。
- **新原语必须携带成本和验证办法。** 包含实现权限、数据/状态语义、额外流量、容量及执行代价；经独立检查进入新版本后才可比较，不能在单次搜索中悄悄改评价规则。

详见[空间审计](RESEARCH_NOTES.md#round-7)及[生命周期设计依据](RESEARCH_NOTES.md#kv-research-scope)。原语的创造力应体现在有约束的组合和可验证的新机制上，不以任意代码修改评价器作为自由度。

<a id="agent-mainline"></a>
## 研究主线与支线

**项目主线已明确为 Agent 主导内存策略探索。** 研究目标是在复杂负载、组合设计空间和有限评价预算下，检验 Agent 能否通过负载理解、假设提出、实验规划与反馈修正，得到更好的可实现策略，或以更少的昂贵评价达到相当的质量。这是待验证的研究假设，当前玩具尚未建立比较优势。

“Agent 是主力”指优化过程中的候选构造、探索方向、工具选择和预算分配由 Agent 主导。数值计算、局部搜索、仿真与正确性检查由确定性工具完成；部署后的地址变换仍由软件或硬件执行。

| 贡献层次 | 需要证明什么 | Agent 的位置 |
| --- | --- | --- |
| 主线：Agent 探索方法与能力 | 具体的候选生成、诊断或实验规划机制在公平条件下相对强搜索器和通用 Agent 循环的增益 | 持续主导探索，是主要研究对象；需要消融、成本统计和泛化评价 |
| 支线：规则发现与固化 | 将探索经验转成可复用启发式，说明适用范围、失效边界和复用成本 | 发现与修正规则，并可将规则作为后续探索工具 |
| 支线：内存机制 | 找到真实瓶颈，提出相对已有机制有增量、可实现且可复用的策略 | 在主线探索中产出有价值的内存策略 |
| 支撑：测量与基准 | 明确真实请求的映射敏感性与优化余量，提供有代表性、可复现的评价任务 | 利用可信任务与工具评价其探索能力 |

真实内存问题的表征与收益空间确认，是主线实验成立的前提。研究目标保持 Agent 主导，但结论必须由证据决定；若某类任务被简单算法充分解决，应保留该结果，检查任务范围和方法机制。[ArchGym](LITERATURE_GUIDE.md#r09) 可帮助设计搜索对照；[AlphaEvolve](LITERATURE_GUIDE.md#r16) 和 [LLAMBO](LITERATURE_GUIDE.md#r17) 提供搜索组织方式的启发，但不能替代直接相关工作的比较。

## Agent 的定位与搜索方法

本项目将 Agent 定位为**利用领域知识持续主导探索决策的主体**。它根据对象、阶段、容量压力及测量提出竞争性的瓶颈假设，自主决定下一步验证什么、调用什么工具以及何时调整假设；最终性能与正确性由工具评价。探索时的反馈适应与部署后的动态切换分开：Agent 可以离线产出确定性状态规则，运行时无需对每次内存请求调用模型。

传统优化方法也能避免穷举。例如，局部搜索修改已有候选的邻近策略，进化算法维护候选群体并产生变体，贝叶斯优化根据历史观测预测哪些候选值得评价。Agent 的收益需要与这些方法比较，不能仅通过胜过随机搜索就认定其全面优越。

建议逐步探索以下分工：

| 组件 | 在搜索中的职责 |
| --- | --- |
| Agent | 提出瓶颈假设与候选结构，决定跨多个操作的修改、诊断实验、工具调用及评价预算分配 |
| 传统搜索工具，后续可选 | 在 Agent 选定的范围与预算内探索局部变体、维护候选多样性或建议下一批候选 |
| 确定性检查与评价工具 | 检查合法性和正确性，测量性能并保存证据 |

例如，在具备合法暂存/提交原语的任务中，Agent 可以假设“写入开销主导”，提出暂存方案；若实测显示容量压力及重计算抵消写入收益，再通过保持最终布局不变的诊断试验区分原因，调整提交或分配策略。这是待验证的决策例子，尚未实现；同一机制也可能由阈值规则或优化器找到，必须直接比较。

对混合方法保持有条件的乐观，以下是待验证的预期：

| 场景 | 预期与限制 |
| --- | --- |
| 少量固定参数、后端很快、只有单一分数反馈 | 传统搜索可能更高效，模型调用成本可能占主导 |
| 存在有实际依据的读写/容量取舍、负载变化和可区分的瓶颈假设 | Agent 可能通过诊断选择和结构性修改节省评价；更多反馈也可能误导，需消融 |
| 跨负载归纳规律或提出扩展原语 | 值得探索，但验证难度和错误风险也随表达能力增加 |

既有玩具已完成文件反馈循环及 V2/V3 比较。下一轮应检验具体决策机制，不以再次搭建循环作为贡献。工具可包括解析估算、整数求解、局部搜索和诊断；Agent 与对照获得相同工具时，工具选择及预算分配仍可成为 Agent 的研究对象。贝叶斯优化等方法需适配实际 DSL，不要求一次实现所有算法。

有限预算内通常只能报告“目前找到的最佳候选”。“局部最优”要求先定义策略邻域，并确认邻域中没有更好的合法候选；不能仅凭若干轮未改善就作出这一结论。

<a id="agent-rule-discovery"></a>
### 支线：Agent 帮助发现可固化的规则

**Agent 帮助发现了一个可以固化的规则。规则一旦写出来，执行它当然可以比重新推理更便宜。这本身可能是 Agent 的一种有价值的定位。**

本项目保留这一认识作为支线贡献。规则可以成为 Agent 调用的工具、后续实验的强基线或最终策略的低成本实现；主线仍需直接检验 Agent 持续探索的能力。

这一认识来自首轮实验：观察到 Agent 对 column 排布的改善后，我们把其中的规律提炼为确定性启发式，后者也达到了相同成绩。因此，最终规则能被简单程序执行，并不抹去 Agent 在发现过程中的潜在贡献；也不意味着每次选择策略都必须调用 Agent。具体过程与事后补充基线的限制见 [实验解读](INITIAL_RESULTS.md#agent-rule-discovery)。

主线与支线应分别评价：

| 目标 | 主要产物 | 评价重点 |
| --- | --- | --- |
| 主线：Agent 主导策略探索 | 多轮诊断、实验决策与给定负载下的具体 DSL 候选 | 同等信息和预算下的策略性能、评价次数、总成本，以及移除 Agent 决策后的变化 |
| 支线：规则发现与固化 | 根据负载特征生成策略的可复用启发式，以及适用条件 | 冻结规则后在未见负载上的收益、失效边界，以及发现与验证的总成本 |

后一种路径可以是：**Agent 提出瓶颈假设 → 工具实验验证 → 提炼并实现确定性规则 → 在未参与规则设计的负载上检验 → 重复使用规则。** Agent 主要参与规则的发现和修订，日常策略生成可以由普通程序完成。评价时应分别记录一次性的发现成本与每次应用规则的成本，不能只报告固化后的低开销。

当前实验只提供了这种工作方式的一个例子，尚未证明规则的新颖性、跨负载有效性，或 Agent 比人工设计及其他规则搜索方法更高效。后续应保留规则的发现过程、适用条件和反例，并与已有领域启发式比较；这类产物补充主线贡献，主线的 Agent 搜索能力仍需独立评价。

后续已完成一次 [规则发现诊断实验](../results/rule_study_v1/report.md)：冻结旧启发式，在六位地址空间中用联合统计修复相关位造成的资源闲置，并枚举全部 720 种位排列作为参照。新规则在两个发现样例上达到排列空间最优，但验证暴露了退化：只统计 bank 内单个位翻转，仍会遗漏多个 row 位同时变化的影响。这为下一轮提出了更具体的规则假设，也说明“固化规则”应同时固化适用条件与反例，不能只保存成功案例。

## 值得检验的假设

以下是候选研究问题，尚未证实其新颖性或收益。

1. **反馈能否修正有代价的错误假设？** 在相同模型调用资源下，比较逐轮有/无新反馈；检查反馈前的预测、之后的行动及最终收益，不能只凭一条成功故事归因。
2. **主动诊断能否比固定流程更省评价？** 让 Agent 与固定流程共享统计、低成本模型和求解器，比较其诊断选择、探索分支保留、重启与预算分配。
3. **何时需要联合设计？** 在选定 KV 子问题中比较静态、顺序优化和合法联合策略，计入容量、转换及依赖；若规则已足够，记录其适用条件而非预设联合搜索胜出。
4. **已学经验何时失效？** 在未参与开发的阶段分布、早停或容量条件下，比较无迁移、固定迁移与 Agent 调整；保存负迁移及最差退化，不只报告平均和最好一次。

初期优先离线搜索或部署前选择策略。运行时可执行小型确定性规则；动态改写已有数据的映射则需另行解决迁移、一致性和切换代价。

## 进入下一阶段的最低证据

先定义小而可信的任务，再做**有来源的负载条件 × 合理默认方案 × 强机制/优化器 × 搜索所得策略**的比较。前期可用标明简化假设的机制模型核验取舍；主张真实收益则必须补齐目标平台证据。静态映射任务可冻结请求轨迹；布局/分配任务需冻结上层事件与执行模型。搜索负载与最终评价负载分开，固定权限、空间、信息及预算。

- 若只比刻意构造的坏映射好，先补齐默认方案与强基线。
- 若目标任务对可控策略不敏感，研究其原因并收窄或停止该任务；调整层级需要新的系统证据。
- 若优化余量存在但简单算法已经解决，说明该任务尚不能支持 Agent 优势；保留负结果，检查有实际依据的负载结构与方法改进，避免只挑有利样例。
- 若相同信息与成本条件下，Agent 在多个未见任务上持续带来增益，再据此支持 Agent 主导探索的主线结论。

20 篇工作已有明确范围的正文记录，仍缺少独立算法复现、目标平台接口确认及新任务实证。下一步从阅读结论收敛到任务规格，不要求先补齐整套仿真工程。若简单解析阈值或强搜索器已充分解决选定问题，应保留负结果；若收益只来自工具、更多控制权限或更大空间，应调整贡献表述。暂停 Ramulator 实际运行与环境安装。


## 如何评价 Agent 的贡献

以下是后续扩展实验的设计要求；当前玩具已实现的预算与异常处理范围见 [运行指南](TOY_GUIDE.md)。

主要目标随任务边界确定并提前冻结：固定流量可用完成时间；涉及 KV 容量、重计算或批处理时，需要包含相应代价的阶段/服务指标和容量约束。不能以行命中率、原始带宽或单个 kernel 的速度代替系统净收益，也不能将 attention 局部加速称为完整推理加速。

已有玩具完成基础比较；新任务按实际机制选择有竞争力的对照，不只搬用旧位活动启发式：

| 方法 | 用途 |
| --- | --- |
| 手工基线，如不进行地址变换 | 提供可解释的起点 |
| 随机搜索 | 检查 Agent 是否优于相同空间内的随机尝试 |
| 简单局部搜索 | 检查基于小幅修改的常规搜索能取得什么效果 |
| 位活动及 column 排布启发式，已实现 | 检查掌握简单地址规律的程序能取得什么效果；后者为首轮后的补充对照 |
| 进化搜索或适配后的贝叶斯优化，后续加入 | 与有竞争力的传统搜索方法比较 |
| 模型一次性提出一批候选，不读取评价反馈 | 观察模型已有知识能提供多少帮助 |
| 母 Agent 根据反馈逐轮提出候选 | 检查反馈循环的增益 |
| 母 Agent 加按需分析子 Agent | 检查分工是否在额外调用成本之外带来收益，不预设固定角色数或每个任务必经 RTL |
| 同一搜索器加入或移除 Agent 候选建议 | 检查混合方法中 Agent 的额外贡献 |
| 相同工具由固定流程调用，或由 Agent 自主调用 | 检查实验选择与预算分配的收益，避免把工具本身的能力归给 Agent |

预算可以从每种搜索方法最多 20 次目标后端评价开始，这只是实验起点。一次评价是候选在固定逻辑工作负载、配置和后端上的执行；同一候选跑多个工作负载分别计数。初始化、校准、诊断、恢复区域的目标评价也计入。低保真估算、正确性检查及 RTL 调用另记次数、时间和资源，不机械等同为一次目标评价。

公平比较需要保持工作负载、合法策略空间、初始条件与预算口径一致，并约定多工作负载结果的汇总方法。失败的后端执行也计入调用预算；非法提案、重复提案、缓存命中和实际执行分别记录，并设置提案数或总时间上限，避免无限重试。

同时记录各方法可获得的负载特征与反馈信息。如果 Agent 读取详细冲突统计，而基线只读取总分，应明确这个信息差异，并通过相同信息条件下的启发式或消融实验区分收益来源。对模型推理、反馈内容和子 Agent 分工的贡献，逐项增加对照，不要求最小版本一次覆盖所有实验。

记录随后端调用次数及总耗时变化的最佳有效结果，以及模型调用次数、token 用量、并行资源和可获得的费用数据。历史数据库构建、提示/基线调参与预训练等可识别成本单列，冷启动与复用场景分开报告。玩具很快时模型可能成为主要耗时；减少仿真次数不自动意味着总时间更短。

独立重复模型探索，复测传统方法的多个随机种子，并保留不参与开发和搜索的任务用于最终评价。固定轨迹重放只检查执行一致性，不等于独立模型重复。测试结果不能反复用于调整策略后，仍被当作未见负载上的表现。

需要真实的模型决策参与，才能评价 Agent 的贡献。手写启发式或人工提交候选可以用于调通接口，但应单独标记。

实验记录应包含 DSL、假设、工作负载标识、硬件配置、后端版本、随机种子和结果。复用结果时，这些影响评价的输入需要匹配。

模型服务、模型版本或标识、提示词版本及可用的生成参数也应记录。评价器能重放已保存的候选，不代表模型每次会重新生成相同的候选序列。

## 已有实验与下一轮 Agent 证据

已按用户确认的四步完成一次 [Agent V2 小规模对照](../results/agent_v2_pilot/report.md)：新轨迹接口、任务与无反馈提案冻结、逐轮 Agent 决策、强基线及消融比较。Agent 相对无反馈提案 1 胜、3 平、1 负；阶段切换任务还输给三个局部搜索运行。主线仍然是 Agent 能力，已有规则作为强对照与开发工具。

随后完成的 [失败复盘](../results/agent_v2_diagnosis/report.md)指出两个可检验方向：探索需要保留有潜力的非最优中间方案，诊断需要区分本批访问与前序积压。原任务中 574 是单次交换邻域的局部最优，但早先放弃的 618 方案一步可到 540；这是事后证据，未修改 Agent 原成绩。复盘新增了诊断工具和提示草案，并提出用“原/新提示 × 汇总/分批反馈”对照分别检验决策与信息的贡献。

该四组对照现已在 [Agent V3](../results/agent_v3_pilot/report.md) 中完成一次小规模试验：四个新模型上下文、三条新轨迹、每条件每任务 20 次评价。密集任务的两个分批反馈组均达到 466，优于汇总组及三次局部搜索的 471；批次间隔任务中，原提示加入分批反馈却由 4308 退步到 4389。结果支持继续检验详细诊断的局部收益，不支持“提示更长或信息更多就稳定更好”。每条件每任务仅一次运行，普通基线也未专门消费分批反馈，不能据此建立稳定或纯反馈贡献。

上述 V2 四步任务已完成首轮，原始协议和结果继续留在归档。V2/V3 的阶段负载均搜索一套静态映射，没有验证运行时迁移。已见反例和 oracle 属于开发资料；它们揭示局部障碍、排队混淆及任务有效空间，不足以解释所有失败，更不是选定系统方向的最终证据。

**下一轮协议建议，尚未冻结或执行：** 在新任务规格成立后，先隔离反馈贡献，再增加主动诊断或工具调度。草案让所有方法共享 5 个随机合法、去重后的初始候选及其评价，计入总计 20 次上限，剩余最多 15 次；这轮不同时测模型 warmstart。

| 组别 | 后续探索 | 要回答的问题 |
| --- | --- | --- |
| A：强传统搜索 | 根据真实反馈搜索，具备多步扰动/重启等适用机制 | Agent 相对强搜索的总体收益 |
| B：模型一次生成 | 只看公共初始数据，一次冻结后续候选 | 初始语义先验与样本能做到什么 |
| C：模型逐轮、无新反馈 | 多次提案，保留初始数据及已提候选，但不读取后续真实结果 | 多次调用自身的作用 |
| D：Agent 逐轮反馈 | 与 C 匹配模型设置及资源上限，依据真实反馈改变策略 | 重点比较 D−C，识别反馈增量 |

四组与旧 V3 的“提示 × 反馈粒度”实验不同。C/D 使用独立上下文；无反馈组隔离日志和工具耗时等泄露路径。合法性、去重、权限和通用工具一致；提案不足、超时、非法与重复均记录，不允许无限重试。共同起点用随机初始化而非为 Agent 人工挑选，具体抽样方式随新空间冻结。

过程证据保存简短的事前假设、指标方向预测、实测与后续行动。候选池质量和从池中选中好候选的能力分别诊断；事后池评价单列费用并与正式搜索隔离。扩展到主动工具调度后，再比较同工具固定流程；若提出新的诊断、记忆或规划机制，还需与同模型的通用反馈 Agent 做移除该机制的对照，四组本身不能证明机制新颖性。完整理由见[反馈协议草案](RESEARCH_NOTES.md#feedback-protocol-draft)，协议数字可在正式实验前调整，但不得根据测试结果追改。

主线的核心问题是：**面对新负载与有限的昂贵评价预算，Agent 能否通过自主诊断、候选构造和实验规划，提高内存策略探索的质量或效率？** 当前仍可通过对话文件接口试验；若要建立可重复、可计量的 Agent 比较，需要进一步记录并固定模型、提示与执行过程。

## 按研究证据推进开发

| 阶段 | 主要产物 | 进入后续工作的条件 |
| --- | --- | --- |
| 1. 收敛最小系统问题，当前重点 | 比较平台权限，选择一个 KV 取舍，形成[任务规格](#minimal-system-task) | 取舍有机制依据；说明已有方法已解决什么、还缺什么；能定义正确性、完整成本和强基线 |
| 2. 建立小模型与强对照 | 最小语义/状态执行、参考数据检查、可手算样例、适用的规则/优化器 | 评价包含所声称的收益及代价；确认有效自由度和优化余量；若简单规则已足够，如实收窄问题 |
| 3. 检验 Agent 的决策贡献 | 冻结任务和协议，独立上下文及重复，质量/成本曲线和过程记录 | 同权限、信息、工具与预算；能区分反馈、调用次数、工具与新空间的作用，报告失败及未见任务表现 |
| 4. 检查模型外有效性 | 有来源的负载、目标平台测量或经校准后端；候选排序与净收益复核 | 新证据不依赖简化模型漏洞；发生排序翻转时先解释原因。Ramulator 恢复运行需另按适配器验收 |
| 5. 有依据地扩展 | 必要的新原语、实现优化、条件式 RTL/综合或分析子 Agent | 每项扩展对应已观察的瓶颈，分别检验其收益、开销和正确性，而非以组件齐全为目标 |

工程成功与研究成功分别判断：前者要求流程可运行、结果可追溯、实验可重放；后者需要对照实验支持 Agent 带来收益。Agent 未胜过基线也是有效研究结果，不影响最小工程闭环的验收。

这份路线图替换旧的“按组件顺序接入”计划。已有玩具闭环、V2/V3、规则诊断和 RTL 导出继续作为基础资产，不能算作新系统任务已验收。当前先完成阶段 1；不以重跑旧任务或立即安装 Ramulator 代替问题定义。

后端和验证按任务选择：软件布局/分配先检查内容、状态及数值；改变控制器才需要相应 RTL，综合得到的缓冲、延迟等成本应反馈性能模型。时钟级命令合法不等于目标控制器已校准，也不证明 KV 内容正确。分析子 Agent 是可选研究机制，不是所有策略的必经环节。

运行契约见[运行指南](TOY_GUIDE.md)，旧实验环境见[首轮解读](INITIAL_RESULTS.md)，后端证据边界见[研究笔记](RESEARCH_NOTES.md#verification-layers)。新协议与新原语尚未实施，当前继续暂停 Ramulator 实际运行及环境安装。
