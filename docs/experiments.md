P5.3 固定迁移验收接通 `fcfs-migration-v1`，计划与负载分开。[手算测试](../tests/test_memory_migration.py)将写满的 8 B 对象从 DRAM 搬到 NAND，再读取并失效：复制有效数据 8 B、复制前端流量 16 B、总目标流量 32 B、预留峰值 16 B、主机缓冲 8 B，最终预留 0 B，NAND 留下一个失效页。总时间 **298 ps**＝读写/链路 226＋生命周期管理 26＋迁移管理 39＋NAND 解绑 7；两种预留时机同分。该批 143 项测试、1,474 次历史回归及七个旧示例通过；固定迁移契约保留，公开示例现已更新为下面的策略模式。

P5.3 迁移策略验收增加 `migration_policy` 与 `fcfs-migration-policy-v1`。[当前示例](../examples/migration_search.json)让 A 经历两个 8 B 代次：第一代写满后读取，第二代写满后直接失效。仅改变触发规则，目的区域仍为 NAND：

| 规则 | 迁移次数 | 有效复制 / 总传输 B | 预留峰值 B | 总时间 ps |
| --- | --- | --- | --- | --- |
| never | 0 | 0 / 24 | 8 | 114 |
| on_full | 2 | 16 / 56 | 16 | 536 |
| before_read | 1 | 8 / 40 | 16 | 342 |

延迟规则跳过了未读代次，仍比不迁移更慢；本用例不构成迁移收益证据。另有容量反例：目标空间稍后才释放时，提前迁移失败；源空间需要及时腾给其他对象时，延迟迁移失败。**时机的作用已经进入执行与约束，不能据此推出通用最优规则。**

本批 **152 项测试**通过，覆盖九种介质组合、未满读取、每代只迁一次、候选目的选择、错误触发与零预算拒绝；仍包含原有复制失败/发布顺序检查。1,474 次历史回归和八个旧任务输入的身份、指标、事件不变（旧固定迁移使用保存的输入核验）。三个规则可沿同一文件会话评价，重复提案命中缓存。仅作 DSL 与执行验收，未开展 Agent 搜索，参数未校准，也不支持并发迁移或布局转换。

<a id="kv-lifecycle-checks"></a>
## K/V 生命周期组合验收

同一[固定输入](../examples/kv_lifecycle_search.json)包含四个槽位：K0/V0 各 64 B，K1/V1 各 128 B；先创建全部对象，再交错追加和读取，最后释放并重建 K0/V0。K0/V0 第一代写满，其余代次只写一半。K 按列、V 按行分组，未模拟数值 attention、GPU 缓存或真实请求到达。两项任务仅把可用 DRAM 区域从 256 B 改为 384 B，读写完全相同。

八个候选由脚本预先指定，未运行 Agent 或搜索算法。除注明的修改外，都在首次访问时预留、初始放 DRAM，并把写满的 K0/V0 迁至 NAND；该可行起点由开发者给出。表中时间是未校准模型的 ps，不能据此比较实际 NAND 与 SSD。

| 候选 | DRAM 256 B | DRAM 384 B | 对应现象 |
| --- | --- | --- | --- |
| 写满迁至 NAND | 4288 | 4288 | 两次复制共 128 B，为后续 K1/V1 腾出空间 |
| 改为创建时预留 | 容量失败，事件 3 | 4302 | 提前预留尚未访问的完整槽位；宽松任务峰值增至 448 B |
| 全程留 DRAM，不迁移 | 容量失败，事件 11 | 2200 | 容量充足时可免除搬移费用 |
| 延至写满后的首次读取前迁移 | 容量失败，事件 11 | 4318 | 读取前，V1 已先要求预留空间；宽松任务迁移峰值为 448 B |
| 改为迁往 SSD 区域 | 3492 | 3492 | 接通主机块路径，不控制 SSD 内部 FTL |
| 仅把 K0 改为列连续布局 | 3668 | 3668 | DRAM 流量增加 96 B，NAND 读取减少 16 页×32 B；逻辑工作和复制量不变 |
| K0/V0 初始就放 NAND、不迁移 | 5630 | 5630 | 同样能满足紧张容量；代价转为初始写入与未满代次的慢介质访问 |
| K0/V0 合成一组并保留迁移规则 | 语义拒绝 | 语义拒绝 | 当前只支持单对象组迁移，不能把共享组当作两个独立迁移对象 |

事件编号从 0 开始。两会话分别消耗 **4 / 7 次**性能评价，5 个拒绝均未计费。有效候选均通过独立内容检查，最终逻辑预留为 0；NAND 编程页不会因逻辑释放被擦除。156 项测试通过，核心执行代码本批未改。结论仅限组合语义验收：迁移并非满足容量的唯一方式，布局、初始目标与迁移时机需一起描述；没有最优性或 Agent 优势结论。

暴露的能力缺口之一是**未满但仍存活的对象**：K1/V1 以及重建后的 K0/V0 不能触发当前迁移，即使为它们选择 on_full。该能力需已写前缀复制、完整槽位预留和发布后继续追加；后续讨论已将它排在 NAND DSL、GC 和详细 SSD 之后，见[当前计划](development.md#implementation-plan)。

复现命令（输出目录须不存在）：

```powershell
python -m experiments.kv_lifecycle_study --output results/kv_lifecycle_p6
```

目录含汇总 `study.json`，以及 `tight/roomy` 两个标准会话的冻结任务、提案、反馈和结果。脚本标记 `is_agent_experiment=false`，记录输入与代码摘要；原始结果默认不入 Git，解释只在本节维护。任一生成的提案都可交给普通 `session-step`，无需专用评价接口。

## NAND 页分布与并行计时验收

[`nand_mapping_search.json`](../examples/nand_mapping_search.json) 固定 2 channel × 2 die、每页 8 B、4 页控制器缓冲；同一组写 4 个逻辑页，再同组读取。`nand_page_mapping` 改变通道/die 轮转顺序与条带页数，后端为 `fcfs-nand-policy-v1`。以下均保持 channel 优先，仅改条带大小：

| 每条带逻辑页数 | 页 0–3 的 `(channel, die)` | 写组结束 / 全部结束（ps） |
| --- | --- | --- |
| 1 | `(0,0), (1,0), (0,1), (1,1)` | 160 / 242 |
| 2 | `(0,0), (0,0), (1,0), (1,0)` | 260 / 362 |
| 4 | 全部 `(0,0)` | 460 / 632 |

三者均为 4 次编程、4 次读取、64 B NAND 传输，差别来自并行与竞争。最小手算另验证：两页编程分到不同通道需 110 ps，同通道不同 die 需 120 ps，同 die 不同 plane 需 220 ps；单页编程为传输 10＋阵列 100 ps。把控制器缓冲降到 1 页后，本例条带 1/4 的完成时间相同。数字只验证未校准抽象模型，**不是器件性能或 Agent 寻优结果**。

170 项测试通过，覆盖非 2 次幂几何、区域基址、选中 die 耗尽、故意错放页、部分更新保护、同块编程顺序、读寄存器占用、缓冲上限、迁移组合与文件会话。V2/V3 的 1,474 次历史回归，以及九个旧任务的身份、指标和事件保持不变（排除 Python 运行耗时）。[测试代码](../tests/test_nand_page_mapping.py)保存手算期望；以下用新目录复现两候选会话，初始设计条带为 1，提案改为 4：

python -m agent_design_search session-step results/nand_pages --proposal examples/nand_mapping_proposal.json
python -m agent_design_search session-finish results/nand_pages
```

该模式不启用 GC，所选 die 满时直接失败；新 GC 模式见下节。当时尚无 SSD 内部 NAND；后续详细模式见[跨层验收](#cross-layer-checks)。磨损和独立 plane 并行仍未实现。

## GC 策略、详细 SSD 与跨层验收

2026-10-20，本轮完成 1–4 的工程交付，没有开始新 Agent 实验。GC 增加阈值与选块候选；详细 SSD 复用 NAND 引擎并限制内部控制器权限；标准会话运行跨层任务；补齐来源记录、MQSim 接口与校准准备。实际外部仿真和真实模型采集仍未进行。

**局部机制验收：** 同一安全状态下，“失效页最多”选择物理块 1，“最早出现失效页”选择块 0，内容均保持正确。详细 SSD 与裸 NAND 在相同整页命令下产生相同 NAND 操作，两条 SSD 命令只增加手算的 20 ps 接口费。主机块小于/等于/大于页及非整除跨页，均检查邻接字节；内部操作被故意删去时，正确性检查会在性能计分前拒绝。

**跨层输入：** [memory_system_study.py](../experiments/memory_system_study.py) 将前面的生命周期序列重复 8 次，包含 K/V 不同读取分组、前缀读取、未满对象提前结束及代次复用。固定混合模组内 DRAM/裸 NAND，另有一个详细 SSD；NAND 均为 2 channel × 2 die，显式前台 GC。只改变 DRAM 区域容量为 256/384 B，其余输入相同。

```

输出目录必须是新目录。跨层记录含源码/输入摘要、两个冻结任务、完整提案/反例、预算和汇总。**195 项测试通过**，覆盖来源冻结、禁止静默丢弃异步字段、跨层容量、内容及后端接口。19 个既有候选的快照/身份/检查/指标/事件/反馈、9 个历史布局用例，以及 292 个归档/旧示例/论文目录文件摘要均保持不变（比较排除运行耗时）。GC 与详细 SSD 的独立文件会话各完成 4 次合法评价并关闭；结果默认不入 Git。

**外部后端边界：** Ramulator 保留只读请求适配；MQSim 可导出原生 SSD trace/XML、验证 bundle、导入聚合结果，裸 NAND 则返回 `needs_driver` 并导出明确的操作依赖协议。请求/结果格式和缺少进程、启动后失败的计费已用夹具测试，未运行真实仿真器。MQSim 原生延迟是截断整数微秒，没有逐请求完成事件；它的固定控制器也不能冒充当前 NAND DSL。详见[MQSim 契约](../agent_design_search/performance/mqsim/README.md)。

## 对象布局开发诊断：有取舍，但静态问题仍容易

2026-10-16。新增空间描述单个 Value 块的分块和四轴排列，固定逻辑追加/读取，按地址生成每组访问涉及的传输粒度。[任务及手算](kv-layout.md)规定了全部假设；此轮用 16×128 个 2 B 元素、64 B 传输、4096 B 容量，基址为 0，无缓存，组间串行，掩码写按整粒度计费。没有 DRAM 周期或 kernel 实测。

下表为总传输量，单位 **KiB（1024 B）**，越小越好：

| 固定任务 | token 连续 | dimension 连续 | 4×8 分块 | 解析选择 | 全空间最优 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 只追加写入 | 4 | 64 | 16 | 4 | 4 |
| 全部写完后读一次 | 132 | 72 | 48 | 48 | 48 |
| 每次追加后读取当前前缀 | 1092 | 192 | 336 | 192 | 192 |

解析选择只检查“一块正好占一个传输粒度”的 5 种整除分块：令 token 分块为 `t`、dimension 分块为 `d`，满足 `t*d=32`，则写次数为 `16*128/d`，读次数为 `128*Σceil(有效前缀长度/t)`。它先用公式选择，再经统一评价器核验；公式推算次数单列，不伪装成后端调用。

完整枚举包括所有容量合法的整数分块和全部 24 种轴排列：每个任务 **960 种写法、290 种不同的元素地址/分配量**。不是 290 个不同分数，也不是任意布局的最优性证明。静态与解析候选共执行 10 次后端（其余语义缓存命中），独立 oracle 共 870 次；本轮不是同预算搜索竞赛。

**支持的结论：** 新 DSL、内容参考检查和统一会话可以运行；不同读写节奏改变最优选择，中间分块可优于两端布局。**尚不支持的结论：** Agent 优势、真实 GPU/PIM/HBM 加速或动态布局机制收益。这里的简单解析规则已解决三个开发任务，不应把静态空间当作新的 Agent 优势证据；下一步应核实目标平台访问方式，再寻找真实剩余取舍。

证据仅保存一份 [study.json](../results/kv_layout_v1/study.json)：任务、候选、指标、实际调用、源码字节哈希及完整枚举的分数摘要。逐项 oracle 可重算，不另存重复结果文件。复现到新目录：`python -m experiments.layout_study --output results/layout_recheck`。三个任务及最优值已公开，只作开发数据。

# 首轮玩具实验：映射有效，Agent 优势尚未成立

运行日期：2026-09-29。后端 `toy-fcfs-v1`，Python 3.10.11，Windows。核心检查 11 项通过。模型与实验约定见 [运行指南](development.md)。

**本轮结论：最小探索闭环已跑通。规则访问流上的糟糕映射可以被明显改善，但简单启发式也能达到本轮 Agent 的最佳结果。** 以下所有周期均为抽象模型输出，不是 HBM 实测，也不是推理吞吐或 token 延迟。

本文保留首轮的结果、验证范围与当时环境，不表示项目最新进度。后续 V2/V3 和 20 篇文献精读已进一步区分有效空间、Agent 反馈贡献与系统取舍；当前将纯地址位搜索作为基础对照，研究判断及开发方向见[研究定位](research-direction.md#literature-to-principles)。下文当时尚未完成的事项不作为当前待办清单。

## 实验条件与原始记录

- 固定硬件参数：4 个 channel × 每 channel 4 个 bank，64 字节粒度、4 MiB 地址容量；最多 8 个映射操作。
- 每条访问流 768 次请求，固定初始空行/队列和 FCFS 调度。
- 每次搜索上限 20 次后端评价，包括 identity、row-XOR 两个共用起点；搜索种子 0、1、2。
- 合法性、可逆性与编译一致性检查先于性能评价。实际调用、缓存和候选 DSL 保存到 JSON。
- 训练选定候选后，使用一条变体访问流做最后评价，另计候选和 identity 两次调用。
- 基线分别保存在 [baseline_v1](../results/baseline_v1/report.md) 和 [baseline_v2](../results/baseline_v2/report.md)；v2 补充事后的较强启发式，原 v1 保留。
- 当前对话的模型实验保存于 [agent_kv_v1/result.json](../results/agent_kv_v1/result.json)，18 份模型提案见 [proposals](../results/agent_kv_v1/proposals)。
- [环境与来源记录](../results/provenance.json) 保存配置、命令、最终源码哈希和模型实验的先验信息边界；它是结束时的快照，不冒充最初运行时的源码快照。

v2 包含 4 种负载 × 4 种搜索方法 × 3 个种子，即 48 次搜索、960 次训练后端评价；还有单列静态基线和搜索后的变体评价成本。这里的“20 次”是每次搜索预算，不是整个项目总预算。

## 不同负载的映射敏感性

下面是确定性映射的完成周期数，越小越好：

| 合成负载 | identity | row-XOR | 位活动：只安排 channel/bank | 位活动：再安排 column |
| --- | ---: | ---: | ---: | ---: |
| 连续访问 | 796 | 796 | 796 | 796 |
| 固定步长 | 9208 | 1944 | 1156 | 796 |
| 模拟 KV 多流 | 18424 | 6132 | 820 | 796 |
| 均匀随机 | 2849 | 2393 | 2516 | 2516 |

固定步长与多流间隔是刻意设计的冲突样例，identity 把许多请求送入同一个 channel/bank。它们适合调试和讲清机制，但会夸大“相对默认”的倍数，不能用来预测工业控制器的收益。

连续访问下没有改善，说明并非任何负载都有显著余量。随机流的有限样本上可以找到更低周期，但在新随机流上并不稳定，见后面的泛化结果。

## 当前对话 Agent 做了什么

模型通过读取 `feedback.json`、保存假设与预测、提交 JSON 候选来决策。评估程序没有根据反馈自动生成这些 Agent 提案。它只执行模型保存的策略。

| 累计训练后端调用 | 提案逻辑 | 完成周期 | 行命中率 |
| --- | --- | ---: | ---: |
| 1 | 共用起点 identity | 18424 | 0% |
| 2 | 共用起点 row-XOR | 6132 | 0% |
| 3 | 用两个 stream 地址位分散到四个 channel | 4600 | 0% |
| 4 | 用剩余 stream 位分 bank，避免同 bank 交替访问不同流的行 | 860 | 93.75% |
| 5 | 再用 token 位利用更多 bank | 820 | 87.5% |
| 7 | 交换位时保留活跃 column 位，减少不必要的换行 | **796** | 93.75% |
| 8–20 | 尝试 channel/bank 混合、不同位选择和相位变化 | 最佳仍为 **796** | 依候选变化 |

第 6 次调用使用纯交换表达，得到 820 周期。并非每次试验都有改善：例如较高 token 位选择 bank 得到 837 周期，某个混合选择得到 838 周期。行命中率更高也未必更快，第 4、5 次的取舍便是例子。

最佳策略为 [best_policy.json](../results/agent_kv_v1/best_policy.json)，五次顺序交换：`(0,12)`、`(1,13)`、`(2,14)`、`(3,4)`、`(4,8)`。其语义依赖固定字段拆分，不能脱离配置直接搬到真实控制器。

768 次传输，每次 4 周期，四个 channel 的理想均分需要 768 周期；最早首个空行准备还需 12 周期。因此当前模型的一个乐观下界是 780 周期。796 已接近这个带宽下界，继续优化同一条轨迹的潜在空间很小。**这不是全搜索空间最优性证明。**

<a id="agent-rule-discovery"></a>
## 为什么还不能说 Agent 更好

起初只安排 channel/bank 的位活动启发式得到 820 周期。观察到 Agent 的 column 改善后，我们补充一个通用规则：按地址位翻转率排序，依次安排到 channel、bank、column。这个规则在第三次评价（两次共用起点之后）就达到 **796 周期**，无需后续搜索。

所以，本轮 Agent 相对弱基线的改善可以被简单规则解释。补充基线是事后诊断，不是预先注册的独立竞赛；下一轮应冻结两者并换新负载再比较。也不能把“LLM 帮助想到一个规则”混同为“运行时必须依赖 LLM 才能找到策略”。

**这也提示另一种价值：Agent 可以帮助发现规则，再将规则固化为低成本的确定性程序。** 固化后的启发式追平 Agent，不能单独否定其发现贡献，也不能证明这种发现方式更高效。后续应分别评价策略搜索和规则发现，具体定位见 [Agent 帮助发现可固化的规则](research-direction.md#agent-rule-discovery)。

| 搜索方法 | KV 训练最佳周期 | KV 变体周期 | 说明 |
| --- | ---: | ---: | --- |
| identity | 18424 | 15884 | 两条访问流各自的起点 |
| activity_local，seed 0 | 820 | **2461** | 较简单的启发式在变体上反而更好 |
| packed_local，seed 0 | **796** | 2988 | 补充的较强训练基线 |
| 当前对话 Agent，一次实验 | **796** | 2988 | 20 次评价中第 7 次已找到最终最佳 |

训练最好的映射在变体上未必最好。本轮也只有一次 Agent 实验，而普通算法各有三个搜索种子，不能据此进行统计显著性比较。
